# Verification records

Post issue-specific check commands, results, and CI links on the GitHub issue. Keep screenshots, traces, PDFs, and response captures in ignored test output or CI artifacts. Do not commit a per-issue verification report under `docs/`.

Use `docs/` for instructions and contracts that remain useful on future runs. Update those documents when the procedure or contract changes; keep dated pass counts and branch-specific results on the issue or CI run.
