# Duplication measurement

Duplication has a narrow, opt-in diagnostic recorder. Set `PRICING_DUPLICATION_TRACE=1` on the API process to write NDJSON traces to `.artifacts/duplication-traces.ndjson`. Set `PRICING_DUPLICATION_TRACE_FILE` to an alternate local output path and optional `PRICING_DUPLICATION_RUN_ID` / `PRICING_DUPLICATION_VARIANT` to labels containing only letters, digits, underscores, or hyphens (up to 48 characters). The recorder is off otherwise. Keep trace files in ignored `.artifacts/` or `test-results/`, with local access restricted to the operator. It sends nothing to a remote service.

The server returns `X-Duplication-Request-Id` only while tracing is enabled. A trace has that opaque ID, a normalized route, outcome/status, source state, a line-count bucket, copied-row and SQL operation counts, response byte count when available, and named elapsed spans. It does not include document IDs, owner IDs, cookies, SQL text/parameters, URLs, or payloads. A process accepts at most 2,000 traces, each with at most 32 spans; a file stops growing at 10 MiB. The first drop emits a local stderr warning. File writes occur after response completion and failures do not change the request result.

`request.total` runs from the early route middleware to response `finish`; `close` without `finish` is marked aborted. `auth.session` includes the session refresh SQL. `transaction.total` includes transaction setup and resolution, including commit or rollback. `transaction.entry` ends when the transaction callback starts, so it includes acquisition and setup and is **not** pure pool wait. `tenant.bind` times the awaited tenant setting. Each SQL span times the whole await, including transport, decoding, and possible wait; `source.lock_read` is **not** pure lock-wait time. `transaction.exit` is callback completion through helper resolution, not exact COMMIT SQL time. `response.encode_send` measures the synchronous `res.json` call, not client receipt. Parent spans overlap their children; never sum them. Keep the unaccounted wall time visible.

For browser diagnostics, build the web app with `VITE_DUPLICATION_TRACE=1`. The page then exposes a bounded `window.__duplicationDiagnostics` array (100 interactions maximum). It records duplication invocation, fetch start, headers, body parsing, React state commit, and the next `requestAnimationFrame` callback. The frame callback is a frame boundary, not proof of physical paint. Clicking **Open copy** starts a separate interaction. Failure and auth-expiry outcomes are recorded. Browser records contain only relative durations, status, outcome, and the server request ID when present. Reloading the page clears them. A normal build leaves this off.

Run `scripts/benchmark-duplication.mjs` only with `BENCH_BASE_URL=http://127.0.0.1:4194` aimed at an API using an empty, isolated disposable database. Set `DATABASE_URL` and `MIGRATOR_DATABASE_URL` explicitly to `127.0.0.1:5433/pricing`; the script refuses other cleanup connections and an occupied fixture database. It creates an owner directly in that disposable database, then signs in through HTTP and verifies the returned owner ID before making any document request. It creates independently authored draft and finalized fixtures at 2, 40, and 350 lines in one database transaction per source; finalized sources use the product finalization API. Fixture setup is outside duplication timing and avoids the draft-save request-size cap. Five warmups and 40 measured requests per case are the defaults; `BENCH_SAMPLES` changes the measured count (1–500).

For a paired comparison, run two API builds against the same disposable database on ports 4194 and 4195. Set `BENCH_CANDIDATE_URL=http://127.0.0.1:4195`, `BENCH_VARIANT`, and `BENCH_CANDIDATE_VARIANT`. The harness alternates variant order for each round and case against the same source fixtures. If `BENCH_CANDIDATE_URL` is absent, it measures one build. Set `BENCH_VACUUM=1` only for an explicitly maintenance-heavy probe: it vacuums both tables outside every measured request. Such results are warm-cache, maintenance-dependent diagnostics, not production latency estimates. Keep trace-on and trace-off runs separate; trace-on/off differences from different runs are not a causal overhead estimate. To estimate observer cost, pair otherwise identical builds with tracing on only in one process.

Every generated copy is deleted via the product API and checked with GET404 outside the measured interval. Raw samples, nearest-rank quantiles, paired savings, and a cleanup ledger are written under ignored `.artifacts/duplication-<run-id>/`. p95 appears only with at least 200 measured samples per case and variant. A normal run removes its fixture owner and marks the ledger `clean`. After an interruption, run `node scripts/benchmark-duplication.mjs --cleanup .artifacts/duplication-<run-id>/cleanup-ledger.json` with the same disposable `MIGRATOR_DATABASE_URL`; recovery checks the synthetic owner marker and removes only that owner and its remaining copies. Recovery uses a database cascade because the API may no longer be running. Neither password nor session cookie is saved to the ledger.

Compare an uninstrumented control, an instrumented control, the instrumented candidate, and an uninstrumented candidate on matched fixtures. Repeat controls when drift is visible. Do not call server response completion browser paint, or subtract independently sampled timings. The populated seed database is a separate workload: read source fixtures only, delete each generated draft through the API, and keep a cleanup ledger. Do not rerun the broad baseline harness, which creates finalized records.

When running repository API or UI tests against the isolated database, point `DATABASE_URL`, `MIGRATOR_DATABASE_URL`, and `BOOTSTRAP_DATABASE_URL` at that same instance. The draft-deletion test uses the bootstrap connection to inspect cascades. The default local URLs target the populated database and must not be assumed to be disposable.

The bulk line copy is one SQL `INSERT ... SELECT`. If the write or its RLS check dominates, investigate a policy or schema change separately with tenant isolation and concurrency tests before touching that boundary. Keep run-specific findings in ignored `.artifacts/` results or the relevant issue.
